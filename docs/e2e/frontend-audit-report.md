# p2party.com Frontend Audit — Synthesized Report

## Executive assessment

The core loop works and is unusually honest for a P2P chat — per-peer mesh delivery outcomes from `sendMessage` are actually rendered, and room onboarding explains its crypto choices clearly — but the UI is **not yet intuitive enough**, for one dominant reason: nearly every failure mode is invisible. A wrong PIN, a PIN-backoff lockout, a mismatched policy, a corrupted file, and an empty room all present identically as silence (eternal "Waiting for peers…" or a button that does nothing), while basic chat conventions (Enter-to-send, hold-to-record, drag-drop affordance) are violated. Meanwhile the flagship privacy machinery (decoys, uniform cells, retransmits) that the home page markets is never shown in-chat, so users can neither verify it nor trust it. Priority one is failure feedback, not new features.

## Top priorities

1. **Handshake/PIN failure black box** — *ConnectAlert + library* (`p2party-js/src/handlers/handleOpenChannel.ts:854`, `roomPinAttempts.ts:66`, `ConnectAlert.tsx:45/62-64`). `connect()` resolves at signaling, so wrong PIN, backoff lockout ("throttled until \<ISO timestamp\>" thrown in a fire-and-forget block), and policy mismatch all collapse into an eternal "Waiting for peers…" badge. This is the single worst UX defect. **Fix:** dispatch per-peer handshake state (pin-mismatch vs transport, plus throttle `retryAfter`) from the `handleOpenChannel` catch block into the room slice; ConnectAlert reopens with "PIN did not match — try again" or a "try again in 4:32" countdown; add a timeout hint on the waiting badge for PIN rooms.

2. **Address-book delete is a confirmed silent no-op** — `src/components/alerts/AddressBookAlert.tsx:56-57`. `deletePeerFromAddressBook(peerId, peerPublicKey)` puts peerId in the `username` slot (signature is `(username?, peerId?, peerPublicKey?)`); nothing is deleted, and the in-place `splice` + `setState(same ref)` suppresses re-render so it *looks* like it worked. `BlacklistAlert.tsx:59-61` shares the splice bug. **Fix:** call `(undefined, peerId, peerPublicKey)` and rebuild state with `.filter()` in both alerts.

3. **File Open/Download silently does nothing on failure** — `src/components/MessageItem/MessageDropdown.tsx:74-86`. `readMessage`'s sentinel strings ("Irretrievable message"/"Invalid message") become `null` and the handlers return silently; real errors go to `console.error`. Worst-possible failure for a file-transfer product. **Fix:** detect the sentinels and surface a visible error (reuse the `sendError` pattern from chat.tsx), distinguishing "still transferring" from "irretrievable."

4. **Delivery outcomes are ephemeral and there is no retry** — `MessageItem/index.tsx:252`, `TransferTray.tsx:107`. Bubbles carry no delivered/partial/failed indicator; dismiss the tray card or reload and all delivery evidence is gone; failed/partial cards offer only dismiss, so a transient hiccup means manual recompose-and-resend-to-everyone. **Fix:** persist terminal `SendMessageResult` keyed by transferId/merkleRootHex, render a compact status glyph on own bubbles (per-peer list on tap), and add a Retry button that re-invokes `startTransfer` with the retained payload.

5. **24-word invites don't carry policy → silent fail-closed joins** — `RoomSetupAlert.tsx:240`, QRCodeAlert. Words carry only the capability; the joiner must manually reproduce the sender's suite + PIN toggle, and a mismatch fails exactly like priority 1 (invisible handshake failure). **Fix:** append a short policy tag to the copied words (e.g. "mlkem1024 pin") and parse on join, or pre-fill from persisted/announced policy; at minimum warn loudly. (This becomes mandatory for v4 — see below.)

6. **TransferTray ergonomics and dual progress narratives** — `TransferTray.tsx:59/87`. Every one-line text message spawns a jargon card ("packing uniform cells", "awaiting authenticated receipts") that never auto-dismisses, in an aside with no max-height; during large-file sends the tray bar pins at 100% (it tracks only chunk prep) while the bubble shows a different "Sent X%". **Fix:** auto-dismiss delivered cards, reserve the tray for files/failures, add `max-height` + `overflow-y:auto`, switch the bar to `savedSize/totalSize` during transfer, unify wording in plain language.

7. **Chat input violates conventions with real safety consequences** — `MessageInput/index.tsx:117` (only Ctrl/Cmd+Enter sends, no hint), `MicrophoneButton.tsx:124` ("Hold to record" is actually tap-to-toggle → hot-mic after release, unhandled `getUserMedia` rejection, no preview before sending audio to all peers), `chat.tsx:60` (`isDragging` set but never read — no drop overlay, dropped files transmit instantly). **Fix:** Enter sends / Shift+Enter newline; true hold-to-record or honest "Tap to record" + timer + preview/discard; render the drop-zone overlay and stage drops as pending attachments.

8. **The flagship privacy layer is invisible** — `MessageItem` destructures only name/size/category/percentage while `readMessage` and the Message record carry `chunksReceivedTotal` (incl. decoys), `chunksReceivedReal`, `retransmits` — zero usages in the site. A stalled receive also just freezes at a percentage. **Fix:** a per-message details view ("N cells — M real, K decoy cover, R retransmit rounds") in MessageDropdown, plus "retransmitting…"/"waiting for sender to reconnect" states driven by `retransmits` deltas and peer state.

## v3 wiring gaps

- `resolveRoomInvite` (`roomAccess.ts:199`) discards `parsedPolicy.specified` and hardcodes all-true — bare `/r#fragment` links to saved PIN/non-768 rooms wrongly hit the policy-conflict path in `useRoom.tsx:86-104`. Return the real `specified` object.
- Past-rooms preview (`RoomItem/index.tsx:68`) reads from Redux where persisted rooms never are → renders the "No message" sentinel as content. Treat the sentinel as empty (or extend readMessage to consult IndexedDB).
- `pressedCancelButtonInRoom${roomUrl}` defaults to `true` in `ChatLayout.tsx:39` but `false` in `SettingsAlert.tsx:59` — the discoverability switch contradicts actual behavior. Share one hook/constant.
- No signaling auto-reconnect while focused, and `isVerified` is never consumed — "connected" UI can show before challenge verification (`chat.tsx:337`).
- `SettingsAlert.tsx:70` clamps padding to literal 1–99% instead of the exported `MIN_/MAX_PERCENTAGE_FILLED_CHUNK` (0.1 floor) — allows out-of-contract 1–9% values.
- Channel selection is dead code atop per-hook-instance `selectedChannel` state (`useRoom.tsx:83`) — would silently not propagate if ChatHeader were ever wired. Lift to shared state or delete.
- `ChatLayout.tsx:68` swallows auto-connect errors (`.catch(() => setAlertIsOpen(true))`) — reopened dialog gives no reason. Thread the message into ConnectAlert.
- Product gap: no mnemonic identity backup/restore UI despite `generateMnemonic`/`keyPairFromMnemonic` existing, while `purgeIdentity` is one click away.

## v4 UI work required (scheduled cover + PQ healing + PIN)

Vendored `p2party@0.12.0` is protocol v3 (no `coverRuntime`, no `pqEpoch`/`healingInProgress`/`prepareHealing` in typings) — everything here is greenfield, gated on vendoring a v4 tarball first.

1. **Boundary + sweep:** vendor v4, add `src/protocol/v4.ts` replacing `v3.ts` (`wireVersion: 3` hardcoded at v3.ts:34); flip guards at `roomAccess.ts:107/137`, key the wasm path off `p2party.VERSION`, and sweep the six-plus "protocol v3" copy sites (home, RoomSetupAlert, ShareDropdown, blog-post, session-lab, SettingsAlert badge) in one change.
2. **Cover status — library first:** `handleOpenChannel.ts:797` calls `installCoverEdge` *without* `onStatusChange` and nothing stores `CoverSchedulerStatus`, so the "never falsely claim cover during a browser-imposed gap" requirement is blocked on a small library API addition. Then add a live starting/active/degraded/suspended pill in the room header ("cover gap — not sending" when suspended) and delete ConnectAlert's hardcoded "immediate delivery" copy.
3. **Scheduled-cover selector + invite transport:** enable the RoomSetupAlert tile with 10s/60s/5min presets mapped to validated `coverCadenceMs`/`coverLanes`/`coverFramesPerCell`/`coverDurationEpochs` (v4 limits: MIN_COVER_CADENCE_MS 1000, MAX_COVER_LANES 16, MAX_COVER_FRAMES_PER_CELL 1024, 25ms slot rule); extend invite params to carry the full policy (base64url of `encodeRoomPolicyV1`'s 32 bytes — invite policy transport is frontend-owned), and extend `policyMismatch` + all policy summaries to show cover mode/cadence. Without this, scheduled-room joins hard-fail the authenticated handshake.
4. **session-lab:** display `pqEpoch`/`healingInProgress` live, add a healing demo leg (`prepareHealing`/`acceptControlFrame`, honoring serialize-before-send), update v3 branding and code sample.
5. **PIN:** no new UI — the existing vault/ConnectAlert/useRoom path matches v4's `ConnectRoomOptions` exactly; re-run the headless-Chromium local-stack E2E (wrong-PIN backoff, `hasRoomPin` reconnect) per the definition-of-done.

## Quick wins

Swap blue-500 focus rings for orange-500; fix the address-book arg order + both splice-in-place bugs; "Shift+Enter for newline" hint; render the existing drop-zone overlay from `isDragging`; unify the `pressedCancel` default; clamp Settings to `MIN_PERCENTAGE_FILLED_CHUNK`; map RoomItem's "No message" sentinel to "No messages yet"; add dismiss/timeout to the `sendError` toast (chat.tsx:412); route ConnectAlert Escape/backdrop through `handleCancelConnect` (ChatLayout.tsx:45); make status badges non-interactive (chat.tsx:317); accept `/r/` in `universalLink.ts:8`.
